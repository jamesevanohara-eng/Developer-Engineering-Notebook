Light and Dark Mode

Entry 03

Light and Dark Mode

Week 3 · September 5–11

Objective

The primary objective for this week was to improve the usability and appearance of my Developer Engineering Notebook by adding a light and dark mode feature. I wanted users to be able to switch between different visual themes while also making sure their selected theme remained active when navigating between pages.

Work Completed

  • Added a light and dark mode toggle to the navigation.
  • Used JavaScript to switch between the two themes.
  • Used localStorage to save the user's selected theme.
  • Updated the CSS to create a separate light-mode design.
  • Tested the theme across multiple pages.
  • Fixed issues where the theme would reset when changing pages.
  • Adjusted the header, navigation, sections, and other elements to work with light mode.

What I Learned

I learned how JavaScript can be used to change the appearance of a website dynamically. I also learned how localStorage can save information in the browser so that a user's preferences can remain active when they move between different pages. This helped me understand how HTML, CSS, and JavaScript can work together to create a more interactive website.

Challenges

One of the biggest challenges was making the selected theme remain active after navigating to another page. The theme initially worked on one page but would reset when another page loaded. I had to use localStorage and make sure that every page loaded the same JavaScript file so the saved theme could be applied consistently.

Reflection

A feature is not finished just because it works once. It needs to work consistently throughout the entire application.

Adding light and dark mode showed me that developing a website involves more than just making individual features work. I also need to think about how different parts of the website interact with each other. Testing the feature across multiple pages helped me identify problems that I would not have noticed by only testing the home page.

Next Steps

  1. Improve the Projects page with project cards.
  2. Add JavaScript project filtering.
  3. Add another interactive feature to the Projects page.
  4. Continue improving the website's overall usability.

Entry 06

Map Modes, User Sign-In, and UI Contrast

Week 6 · September 29–October 2

Objective

The primary objective for this week was to build out core interactive features for the Community Repair App. I aimed to enhance the map capabilities, implement user interaction tools like comments and sign-in, and improve visual accessibility by refining the theme's contrast.

Work Completed

  • Added map view options, allowing users to toggle between standard and satellite Earth views.
  • Implemented a basic user sign-in system to support user accounts.
  • Added a comment section for community feedback on repair issues.
  • Created a "Like" button enabling users to support or agree with reported issues.
  • Updated the visual theme to improve overall contrast and readability across the app.

What I Learned

I learned how customizing map views can significantly improve spatial clarity for users identifying local repair needs. I also gained experience with basic authentication flows and dynamic user engagement features like likes and comment threads.

Challenges

One challenge was ensuring high visual contrast across dark and light UI states without sacrificing the aesthetic design. Another challenge was managing state for interactive user actions like signing in and saving liked issues.

Reflection

Interactive features transform a static map into an active community tool where users can collaborate on local solutions.

Adding feedback loops like comments and agree buttons made the prototype feel much more functional and community-driven. Higher UI contrast also makes the platform far more accessible to all users.

Next Steps

  1. Refine user authentication and session management.
  2. Enhance map pin details and issue tracking workflows.
  3. Gather user feedback on the updated UI contrast and design.
  4. Prepare documentation for full app testing.

Entry 07

Branding, User Accounts, and Community Outreach

Week 7 · October 5–9

Objective

The primary objective for this week was to continue improving our Community Repair App by strengthening its visual identity, exploring how it compares to the existing solution used by the City of Fishers, and beginning to plan community outreach. We also started developing user registration and login features to support a more personalized user experience.

Work Completed

  • Added a logo to the Community Repair App to establish a recognizable visual identity.
  • Began drafting emails to send to individuals and organizations around Fishers, Indiana, to introduce the project and explore opportunities for feedback and support.
  • Compared our app with the existing community repair platform used by the City of Fishers to evaluate differences in features, functionality, and user experience.
  • Started implementing user login and sign-up functionality, although both features are still under development.
  • Updated the app's color scheme to use higher-contrast blue and orange colors, improving readability and giving the interface a more distinct appearance.

What I Learned

I learned that developing a useful application involves more than writing code. Branding, user experience, community outreach, and understanding existing solutions are also important parts of building a successful product. Comparing our app with the platform already used by Fishers helped us think more critically about what our project could offer and how it could be improved. I also gained more experience planning authentication features and considering how user accounts could support future functionality.

Challenges

One of the main challenges was determining how our app could distinguish itself from the existing platform used by the City of Fishers. We need to understand what already works well and identify areas where our application could provide additional value. Another challenge was beginning to implement login and sign-up functionality, since user accounts introduce additional complexity and require further development and testing. We also needed to balance the app's visual design with sufficient contrast and readability.

Reflection

Building a useful application means understanding not only how it works, but also who it serves and what makes it valuable.

This week helped me look at the Community Repair App from a broader perspective. Adding a logo and updating the colors made the project feel more recognizable, while comparing it with the existing Fishers platform helped us think about its purpose and potential advantages. Drafting outreach emails was also an important step toward connecting our development work with the community we hope to serve. Although the login and sign-up features are far from finished, starting their development gives us a foundation for future improvements.

Next Steps

  1. Continue developing and testing the user login and sign-up features.
  2. Refine the app's visual design and ensure consistent color contrast throughout the interface.
  3. Review the comparison with the existing Fishers platform and identify opportunities to improve our app.
  4. Finalize and send outreach emails to relevant individuals and organizations in Fishers.
  5. Gather feedback and use it to guide future development.
  6. Continue improving the app's usability and core community repair features.
